# 接口约定

`contract/` 是三人唯一公共协议，B 负责维护。接口实现放各自目录，不在公共目录塞 Android 组件、数据库或 UI。

## 交接顺序

1. A 的 CaptureGateway 输出 CapturedContent；读正文前检查用户授权。队列只由 B 协调器消费。
2. B 协调器检查 session、来源时效，调用 A 的 InferencePipeline；B 的 TaskContextProvider 供应现有任务。
3. A 返回 AnalysisOutcome。模型不可用返回 Unavailable；解析错误返回 Invalid；Success 可以没有建议。
4. B 的 AnalysisCommitter 校验并通过 TaskRepository 写入；候选/正式任务共用 TaskSnapshot。
5. C 通过 AssistantFacade 的 Flow 展示，UserCommand 提交操作。系统提醒由 B 的 ReminderGateway 处理。

## 标识与版本

- TaskSnapshot.id 不因确认/更新/恢复改变。TaskRef(id, revision) 必须来自最新展示或检索快照。
- SourceEvidence.fingerprint 表示稳定来源事件身份，fragmentKey 区分同一来源里的不同任务。不能用读取时间、内容前30字或模型摘要作为唯一身份。
- 没有消息原生 ID 时如何构造稳定身份仍须 A/B 用真机样本共同验证。pageFingerprint 只减少重复处理画面，不能代替事务去重。
- 已确认实质变化写 ChangeProposal(baseRevision)，接受时再次核对；冲突由用户给 chosen 值。
- ReminderPlan.generation 用于使旧闹钟/旧通知动作失效，不能只用 taskId 判断。

## 时间与状态

- publishedAt 是原始发送/发布时间，observedAt 是读取时间；未知发布时间保留 null 并展示未知标签。
- TaskTime 区分 NONE/DATE/DATE_TIME/UNRESOLVED；提醒时间单独记录。
- DRAFT/CONFIRMED 与 OPEN/COMPLETED/EXPIRED 是两个维度，待确认任务也能超时。
- 已知超过来源有效期的内容在推理前跳过，提交前复核；未知来源仍按普通任务规则处理。

## C 提交操作与错误处理

- `facade.dispatch(UserCommand.Confirm(TaskRef(id, revision)))`；成功后等待 Flow，不在 UI 复制一份“已确认”任务。
- APPLIED：已执行；ALREADY_APPLIED：重复操作无副作用；STALE：重新载入最新数据；INVALID：解释限制；NOT_FOUND：更新列表；NOT_IMPLEMENTED：开发中，不能显示成功。
- 任务保存成功不代表提醒已安排。提醒请求已写库、系统调度成功、通知实际显示是三个不同结果。
- 详情使用 facade.observeDetails(taskId)；unavailableReason 非空时说明查询尚未接通，不能把空 sources 当成真实无来源。当前 C 页面仍用基本字段，待 C-04 接详情。
- 单项提醒设置使用 UserCommand.SetReminder；校验提前量/具体提醒时刻并更新 generation 由 B 完成。
- 设置由 facade.updateSettings 更新，不让 C 或通知动作绕过业务门禁直接改偏好文件。
