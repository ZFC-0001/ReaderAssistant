# Android 本地 AI 事务助手功能文档

版本 1.0　日期 2026年11月7日

## 一 我们要做什么

开发一款 Android 本地 AI 事务助手。用户授权后，在浏览微信聊天、微信公众号文章和 QQ 聊天时，助手持续识别当前可读取的内容，发现与用户有关的任务，提取时间、地点和要求。用户确认后，保存为本地待办，并按设置提醒。

助手还需要持续维护同一事务：关联不同来源的信息，补全缺失内容，发现改期、要求调整或取消，提示用户确认更新，减少重复录入和反复核对。

小型 AI 模型随安装包提供，核心识别、理解、关联、存储和提醒流程在手机本地完成，安装后不依赖联网下载模型或云端推理。

## 二 使用流程

1. **开启识别**：用户选择允许读取的应用，完成必要的系统授权。
2. **正常浏览**：助手持续读取已授权应用当前可获得的页面内容。
3. **理解和匹配**：过滤过旧内容，结合已有任务分析新信息，判断是新任务、补充内容还是任务变更。
4. **提示待确认**：按用户设置显示摘要卡片，或进入待确认队列。
5. **确认保存**：用户确认或修改后确认，原候选直接成为正式待办，不重复填写。
6. **提醒和完成**：到点发送提醒，用户可直接完成或稍后提醒。
7. **持续更新**：后续信息继续关联原任务；正式任务发生变化，确认后才更新。

## 三 核心功能

### 1 持续感知与控制

第一版以微信聊天、微信公众号文章和 QQ 聊天为主要场景，识别范围按应用控制，不单独设置某个群聊或私人聊天的排除规则。

用户从常驻通知查看识别状态、暂停或恢复识别，不设置常驻小浮球。暂停识别后，已经安排的任务提醒照常生效。

只处理实际可读取的当前页面，不自动翻聊天历史，不读取聊天数据库，不保证未展示的内容能够被发现。

### 2 本地理解与任务提取

AI 提取任务内容、时间、地点和要求，区分待完成事项与过去经历，只关注交代给用户本人或用户所属群体的任务。

无法确定是否与用户有关时，标注“可能与你有关”，仍按普通任务规则提示。无需用户填写、维护昵称；优先使用可读取的界面线索，身份不明确时保留不确定性。

待确认和已确认任务是 AI 的主要上下文。已有任务缺少时间等信息时，后续消息优先匹配、补充原记录。只有已有任务和当前页面不足以解释时，才使用少量自动清理的临时片段，不要求用户设置普通聊天的保留时长。

### 3 新任务的三种提示模式

| 模式 | 规则 |
| --- | --- |
| 按时间区分 默认 | 未来24小时内的任务显示提示卡，其余进入队列；时间范围可自定义 |
| 始终使用提示卡 | 所有新任务通过提示卡提示 |
| 始终进入待确认队列 | 所有新任务先进入队列 |

提示卡显示任务摘要、已知的任务时间、实际提醒时间及不确定项，用户可以直接确认或进入修改。

卡片未操作就收起，任务进入待确认队列。返回桌面时统一提示待确认内容；应用之间切换时不提示。重复读到同一内容，不重复新增、计数或弹卡。

对于临近开始的事项，提示卡本身已经完成告知，不额外增加补提醒流程；已经过去的默认提醒时刻不直接登记为闹钟，卡片明确显示实际提醒状态。

### 4 待确认与正式待办

待确认和正式待办共用同一条任务记录。确认时改变任务状态，已有信息全部带入，不复制任务，也不要求重新输入。

用户可以在确认前修改任务，在正式待办中查看、编辑并手动标记完成。AI 不自动判断任务已经完成。

没有明确时间的任务，可以保存为无提醒待办。只有日期的任务保留日期，不自动补出具体时刻，也不默认设置提醒。相对日期应展示解析结果；推断不可靠时保留待澄清项。

### 5 跨来源关联与去重

同一任务在不同聊天或文章中出现时，关联到原任务，不重复录入。

尚未确认的同一事务候选，可靠匹配后自动合并为一项，展示多个来源，并支持拆开错误关联。相似标题或缺少时间，不能单独作为合并依据。

后续信息补充到原任务：未确认的候选直接补充，已经确认的任务涉及时间或要求变化时，生成变更建议。

来源时间冲突且无法确定哪个有效时，并列显示时间和来源，由用户选择，AI 不擅自预选。

### 6 任务变更与超时恢复

已确认任务发生改期、要求调整或取消时，立即显示变更提示卡，展示原内容、新内容及来源。此规则适用于三种模式，包括“始终进入待确认队列”。

用户确认前，原任务及原提醒不变；确认后更新原记录，并调整相关提醒。同一变更的重复读取不重复提示。任务进行期间保留必要来源和变更历史，供核对及更正。

超时任务收到明确延期通知时，可以根据保留摘要匹配原任务，弹卡询问是否延期并恢复。确认后恢复原记录，不新增重复任务；确认前仍保持超时。已经清理的旧原文和历史不还原，新的延期信息作为新来源保留。重复旧内容不会恢复任务，已完成任务不自动恢复。

### 7 提醒与任务状态

默认提前30分钟提醒，用户可修改全局默认值，也可单独调整某项任务。提醒通知提供“完成”和“稍后提醒”，点击正文进入任务详情。

“稍后提醒”一次点击默认延后10分钟，时长可自定义，只调整提醒，不改变任务时间。

任务时间过去后标注“已超时”，提前提醒时间过去不算任务超时。只有日期的任务在该日期结束后标记超时；完全没有日期和时间的任务不自动超时。超时不等于完成。

### 8 历史内容过滤与数据清理

聊天消息和公众号文章默认只处理最近7天内容，天数可自定义。依据原始发送或发布时间判断，不把读取时间当成发布时间。

已知超过期限的内容，不新增任务、不弹卡、不触发变更。来源日期无法确认时，仍可提取任务，标注“来源日期未确认”，按普通规则处理。

七天规则不删除已经收录且仍在进行的任务；已有任务继续用于匹配新的补充和变更。

任务完成或超时后，清理详细来源原文、变更历史和相关冗余缓存，保留简要任务、状态及必要去重信息。清理后仍能标注“已完成／已超时”，也不会因再次读到旧内容而重复创建任务。

## 四 主要页面

| 页面或入口 | 主要内容 |
| --- | --- |
| 今日概览 首页 | 今天的待办、即将到来的任务、待确认数量及列表入口 |
| 待确认队列 | 候选任务、不确定项、待确认变更及超时标记 |
| 正式待办列表 | 已确认任务、任务时间、提醒状态及完成操作 |
| 任务详情 | 任务字段、可保留的来源、变更差异和提醒设置 |
| 设置 | 授权应用、提示模式、时间范围、默认提醒、稍后时长和来源有效期 |
| 常驻通知 | 当前识别状态，以及暂停、恢复入口 |

## 五 隐私与用户控制

核心数据处理和存储均在本地，限制读取范围和原文留存，不保存完整聊天档案或持续录像。提供暂停识别、撤销授权、删除本地数据的入口；日志、临时图片及备份也需遵守相同的数据保护要求。

本地运行是设计要求，实际隐私保护还需检查依赖、日志、缓存和备份，不能仅凭模型在本地运行就声称绝对安全。

## 六 第一版范围与实现默认

第一版必须完成基础任务流程，以及跨来源关联、信息补全、变更确认、去重和超时延期恢复。开发顺序先基础流程，再关联与变更，这些关联能力不降为可选探索。

校园 App 接入、专门读取软件数据和通知内容采集排在后续。第一版不做云端推理、跨设备同步、自动回复消息或代用户执行事务，不破解或绕过受保护页面，不承诺任意 App 都可读。

以下两条为可调整的实现默认值：

- 按时间区分模式中，没有具体时刻或时间仍待澄清的新任务先进入队列；另外两种模式仍遵循用户设置。
- 主动稍后提醒即使超过任务时间仍执行，使用保留摘要，保持超时状态，不自动恢复任务；任务完成后旧提醒和旧稍后操作失效。

## 七 功能验收重点

1. 相同内容重复读取、滚动重现或重启后再读，不重复创建任务和提醒。
2. 候选确认后仍是原任务；后续补充、跨来源关联和变更不会重新录入一条。
3. 正式变更及延期恢复均由用户确认，时间冲突不自动选择。
4. 提示模式、回桌面汇总、默认提醒和稍后提醒符合规则。
5. 七天过滤、未知日期标记、超时判断和数据清理符合规则。
6. 核心流程可离线使用，暂停识别不影响已有提醒。

本文定义产品需求，不代表全部功能已经实现。微信及公众号可读性、身份与日期识别、本地模型准确率和资源消耗、卡片交互及后台提醒可靠性，仍需通过对应真机测试验收。
