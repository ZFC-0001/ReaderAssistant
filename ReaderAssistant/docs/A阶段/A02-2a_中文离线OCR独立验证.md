# A-02.2a 中文本地OCR独立验证

日期：2026-11-11。当前结论：相同白底合成图对照中，原图仍1/3，黑白增强完整命中3/3且离线运行；增强候选在该固定样本下通过。真实微信页面效果未测，不能宣称通用OCR准确性或100%字符正确。

## 这一步与现有工程的关系

本阶段先独立验证随包中文模型能否离线识字。独立包名`com.example.localtaskassistant.ocrprobe20261111`，应用名“中文OCR离线自测”，使用自身生成的三行测试图，不访问微信、通知、相册或无障碍，不覆盖主助手、不清主助手数据。

正式工程的`capture/ocr/LocalOcrAdapter.kt`仍为原占位实现。候选代码保存在本A目录`候选代码/A02-2a/`，以及工作区`work/a02-2a/candidate/`，不加入正式src/main。独立Android构建目录为`work/ocr-spike/`；本次没有改正式工程的Gradle、Manifest、公开契约或B/C代码。复制的5个公开契约文件逐字节保持原样，仅供独立编译。

## 技术选择与隐私核对

- 候选依赖：`com.google.mlkit:text-recognition-chinese:16.0.1`，选随包模型，不选Google Play动态下载方案。独立APK已核对内含Hani/Latin等模型资产及4架构原生库。
- APK实测47138124字节，约47.1MB，不能用官方单模型增量估算冒充本包实际体积；本开发包包含4个ABI。
- 官方声明输入/识字输出在端侧处理，但SDK有使用统计机制。因此单靠“ML Kit本地识字”不足以宣传SDK完全不联网。本测试包明确移除INTERNET，打包后确认不存在；保留ACCESS_NETWORK_STATE仅用于检查是否有网络，不授予建立网络连接的能力。
- 首次有效测试前由工具确认飞行模式=1、Wi-Fi=0，应用内无先前识字报告；自测入口也要求飞行模式且无活动网络才调用模型。
- 不声称已证明整个应用进程首次启动一定离线：安装后系统notLaunched状态未确认，后续打开返回WARM。可以确认的是本轮有效识字运行开始/结束均无活动网络，且APK没有直接联网权限。
- 只在内存生成Bitmap/RGBA，识字原文仅显示在本自测页面，不写报告、日志、图片或相册。私有报告只保存匹配数、耗时、网络状态和清零结果。

## 候选代码职责

1. `LocalOcrAdapter`保持公开TextRecognizer/OcrFrame/TextBlock接口；接收紧密排列RGBA8888，转换到Bitmap后调用随包中文模型，返回画面位置排序的文字，不猜聊天身份或日期。
2. `OcrInputRules`检查尺寸、字节数与通道顺序，单帧最多4194304像素；超过250行/64000字符直接失败，不返回未标记的部分页；保留重复文本，不过滤“取消/延期”。
3. 每个适配器至多一项SDK任务；等待超时8秒或上层取消不会谎称原生SDK已中止。完成回调负责关闭client、回收Bitmap、归还槽位，调用方finally清零原RGBA。无法强制取消原生任务及极端挂起资源占用仍属于待验证边界。
4. `OcrOfflineProbeActivity`是独立自测入口，只生成固定测试图并调用同一候选适配器；不作为C的正式页面或任务识别功能。

## 固定测试条件与通过标准

在1400×480白底图上，以52像素系统默认字体绘制三行：

```text
明天下午3点提交实验报告
地点信息楼302
周五18点30分前完成报名
```

只移除识字输出中的空白后做原句子串匹配，要求3/3；不模糊替换数字、文字，不用预设文本填补识字结果。此门禁是小型合成图自测，不是完整OCR评测集，1/3整句命中也不能解释成字符准确率33%。
