# A-02.1 微信自动取画面：实现与测试

日期：2026-11-11。当前结论：微信聊天/公众号的竖屏自动取画面基础验收通过；已验证通知停止、到期停止、同一有帧会话锁屏停止、取消授权不启动、离开微信不新增处理帧及返回继续浏览恢复。横屏/旋转按用户明确决定暂不测试，不阻塞竖屏范围内的后续OCR；不宣称横屏通过、所有页面可捕获或文字已识别。

## 这一步做什么

用户点击开发验证入口后，由系统请求屏幕捕获授权。用户必须选择“共享单个应用→微信”，随后正常打开自己的测试聊天或测试文章；应用自动取得画面，不要求用户手动截图。本步只统计帧数、尺寸、耗时和少量像素信号，不识字、不提取任务、不接业务库。

微信聊天与公众号文章分开验收。取得有亮度变化的画面不等于文字清晰可读，也不等于OCR或任务识别成功。

## 运行边界

- 本次验证入口仅支持Android14及以上，且仅允许debug包进入；不改变工程minSdk。
- 每一轮都重新请求系统授权。授权结果只在本轮Activity→Service传递，不写文件、不跨重启恢复、不复用旧VirtualDisplay令牌。
- 授权成功后先启动指定类型的前台服务，再取得MediaProjection；使用系统回调接收停止。每个授权只创建一次VirtualDisplay，尺寸变化时resize/更换Surface。
- 需开启助手识别、选择微信、无障碍连接、手机亮屏解锁，且活动根包名为微信，才检查像素。恢复后先丢弃两次采样，减少旧缓冲参与统计。
- 系统的单应用选择无法通过公开MediaProjection接口反查目标包名。必须由用户在系统选择器手动确认微信，真机记录中单独记载；不能把代码门禁说成已经证明系统只捕获微信。
- 切到其他应用时丢弃画面，不交给像素检查/OCR；在此spike中授权流与ImageReader可能继续存在，直到用户停止、系统停止、锁屏触发停止或两分钟到期。
- 通知栏和验证页可停止；系统停止/进程销毁不自动续录。释放Image、ImageReader、VirtualDisplay、MediaProjection及工作线程的真机效果仍待测。
- 帧只在内存处理，Image在finally关闭。磁盘仅写应用私有`files/wechat-projection-probe/report.json`统计；不保存图片、视频、原文或授权令牌，不声明网络权限、不请求音频。
- 暂不以这个受控两分钟实验宣称后台长期稳定、任意页面可捕获、或受保护窗口可读。用户选全屏、选错应用时本轮应取消重试，不作为范围通过证据。

### A范围修复

旧版检查锁屏的位置位于ImageReader新帧回调内。没有新帧时这条检查无法运行，代码存在独立于平台表现的停止触发缺口。

3. 停止路径先撤销系统MediaProjection，再由工作线程释放图像和显示资源，避免等待可能阻塞的窗口元数据查询。真实释放效果仍以复测验收。
4. 增加纯逻辑ProjectionScreenGuard及5项测试：亮屏解锁、熄屏未锁、亮屏锁定、熄屏锁定、没有任何Image仍可结束会话。
